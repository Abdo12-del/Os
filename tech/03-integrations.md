# الجزء الأول — بوت الموافقات على تيليجرام

## ما يفعله البوت
1. يرسل **الملخص اليومي** 7:00 إلى `🎛️ مركز العمليات`
2. يرسل كل **`pending_action` جديد** مع أزرار القرار
3. يستقبل قرارك ويكتبه في `pending_actions` (`approved` / `rejected` + `decided_by`)
4. ينفّذ **عبر تطبيقك** — `approve_and_execute()` — لا بنفسه

## ما لا يفعله البوت أبدًا
- ❌ لا يرسل لولي أمر. ❌ لا ينشر على قناة. ❌ لا يكتب في جدول مالي.
- ❌ لا ينفّذ `publish_post` ولا `send_parent_msg` **حتى بعد موافقتك**. هذان يبقيان يدويين من حسابك.
- ❌ لا يقبل أمرًا من أي `chat_id` أو `user_id` غير المثبَّت في إعداده.

## الأوامر

| الأمر | ماذا يفعل |
|---|---|
| `/brief` | الملخص اليومي الآن (نفس صيغة `03-head-of-operations.md`) |
| `/pending` | الاقتراحات المعلّقة، مرتّبة بالأقدم، مع `risk` |
| `/approve <id>` | موافقة → `decided_by='founder'` → التنفيذ في تطبيقك |
| `/reject <id> <سبب>` | رفض **بسبب إلزامي** — السبب يُعلّم الوكيل |
| `/edit <id>` | يفتح المسوَّدة لتعدّلها، ثم يعيد إدخالها `pending` |
| `/audit <agent>` | آخر 20 سطرًا في `agent_audit_log` لهذا الوكيل |
| `/revoke <agent>` | **زر الطوارئ:** `revoked_at = now()` → الوكيل يتوقف فورًا |
| `/status` | الطابور المتراكم + توكنات قاربت الانتهاء + أشهر لم تُغلق |

## تصميم رسالة الموافقة

```
🟡 اقتراح #88 — المحاسب
التصحيح: دفعة S-104 بمبلغ 3000 دج
مسجَّلة في: نظام الأولياء (2026-11-03)
غير مسجَّلة في: نظام المحاسبة
السبب من البيانات: غير معروف — المرجع BP-88213
المرجع: pay-104-2026-11

[ ✅ وافق ]  [ ❌ ارفض ]  [ ✏️ عدّل ]
⚠️ الموافقة تُنفَّذ في تطبيقك. لا شيء يُكتب قبلها.
```

**قواعد الرسالة:**
- **`risk` ظاهر دائمًا** — 🟢 🟡 🔴 في أول سطر. 🔴 **بلا زر موافقة**: «هذه تحتاج مكالمة/قرارًا مباشرًا، لا زرًا».
- **المرجع ظاهر** — لا توافق على رقم بلا مرجع.
- **لا تنفيذ بلا `idempotency_key`** — الضغط مرتين لا ينفّذ مرتين.
- **الرفض يطلب سببًا** — السبب يعود للوكيل كتعليمة، وهو الطريقة الوحيدة لتحسّنه.

## التثبيت الأمني (لا تتجاوزه)

```
ALLOWED_CHAT_ID   = <معرّف مجموعة 🎛️ مركز العمليات>
ALLOWED_USER_ID   = <معرّفك أنت وحدك>
BOT_TOKEN         = متغير بيئة، لا في الكود، ولا في Git
```
- أي رسالة من غير `ALLOWED_USER_ID` في غير `ALLOWED_CHAT_ID` → تُتجاهل **وتُسجَّل** في `agent_audit_log` كـ `outcome='refused'`.
- البوت **لا ينضم** إلى أي مجموعة أخرى. لا تضعه في قناة الأولياء. أبدًا.
- **Rate limit على الأوامر:** 20/دقيقة. تجاوزها = تسجيل لا تنفيذ.

## الملخص اليومي المجدول

```
cron: 0 7 * * *   →   GET /api/v1/ops/daily-brief   →   bot.send(ALLOWED_CHAT_ID, brief)
```
- إن فشل بناء الملخص (نقص بيانات)، **يُرسل الملخص ناقصًا مع قسم «ماذا تعطّل»** — لا يُكتم. الكتم يعني أنك لن تعرف أن النظام تعطل.
- لا يُعاد الإرسال عند الفشل أكثر من مرتين، ويُنبَّه على الفشل.

# الجزء الثاني — خادم MCP

## لماذا MCP
يعطي وكلاء Claude أدواتك **كنطاقات محدودة**، بدل أن تلصق ملفات يدويًا. مفيد من المرحلة 2 فصاعدًا — **وليس شرطًا للمرحلة 1**، التي تعمل بمشروع Claude وملفات المعرفة وحدها.

## الأدوات المعرَّفة

### نطاق `marketing:read`
| الأداة | المدخلات | تُرجع |
|---|---|---|
| `get_funnel` | `from`, `to` | قمع الفترة + `by_source` + `missing` |
| `list_leads` | `status`, `limit`, `cursor` | مهتمون **بلا هاتف ولا عنوان ولا مبلغ** |
| `get_content_calendar` | `week` | خطة الأسبوع المعتمدة من `marketing/` |

### نطاق `finance:read`
| الأداة | المدخلات | تُرجع |
|---|---|---|
| `get_reconcile` | `month` | الفروقات + `known_normal_reason` |
| `get_summary` | `month` | التدفقات الثلاثة + تنبيهات + `missing` |
| `get_teacher_statement` | `month`, `teacher_id` | مستند الأستاذ — **بـ `basis: null` إن لم يُحسم** |

### نطاق `actions:propose` (الكتابة الوحيدة)
| الأداة | المدخلات | تُرجع |
|---|---|---|
| `propose_correction` | `source_ref`, `proposed`, `reason`, `idempotency_key` | `{ id, status: "pending" }` |
| `propose_post` | `platform`, `text`, `pillar`, `idempotency_key` | `{ id, status: "pending" }` ⚠️ لا يُنفَّذ آليًا |
| `propose_lead_message` | `lead_id`, `text`, `idempotency_key` | `{ id, status: "pending" }` ⚠️ لا يُنفَّذ آليًا |
| `propose_teacher_payout` | `teacher_id`, `month`, `basis`, `amount`, `idempotency_key` | يرفض إن كان `basis` غير محسوم |
| `log_action` | `action`, `target`, `row_count`, `outcome`, `note` | `{ ok: true }` |
| `list_open_actions` | `agent?` | الطابور المعلّق |

## قواعد الخادم
1. **كل أداة قراءة تُرجع `source` و`missing`.** أداة بلا `missing` ستُغري الوكيل بالاختراع.
2. **لا أداة تنفيذ.** لا `execute_action` ولا `publish` ولا `send`. التنفيذ في تطبيقك بزر الموافقة.
3. **`propose_*` تفشل إن غاب `idempotency_key`** — فشل صريح، لا تجاهل صامت.
4. **`propose_teacher_payout` ترفض `basis` غير المحسوم** — القاعدة 10 للمحاسب مفروضة في الكود كذلك.
5. **كل استدعاء يكتب في `agent_audit_log`** — بما فيه المرفوض و`unknown_asked`.
6. **الخادم يقرأ من `views` مخفّضة، لا من الجداول** — نفس مبدأ `01-schema.sql` القسم 5.
7. **توكن لكل وكيل** — الخادم يرفض أي استدعاء بتوكن لا يطابق نطاق الأداة (`403` برسالة تذكّر بالقاعدة).

## هيكل مقترح (Node أو Python — أنت تختار)
```
mcp-academy/
├─ server.(ts|py)        # تعريف الأدوات + فحص النطاقات
├─ db.(ts|py)            # اتصالات read-only، لكل وكيل اتصاله
├─ views.sql             # الـ views المخفّضة (من 01-schema.sql القسم 5)
├─ audit.(ts|py)         # كتابة agent_audit_log في نفس المعاملة
└─ .env                  # التوكنات — خارج Git (.gitignore)
```
> ⚠️ `.env` و`exports/` و`finance/report-*.md` **خارج Git** — `.gitignore` مضبوط بالفعل على `exports/` وملفات CSV/Excel. أضف `.env` إن لم يكن.
