# ops/ — مركز العمليات: محرّك يعمل، لا واجهة عرض

> **الفرق عن بقية المستودع:** كل ما خارجه وثائق تصف النظام.
> هذا المجلد **النظام نفسه يعمل**. الأرقام محسوبة من قاعدة بيانات في كل طلب،
> والموافقة تُنفَّذ فعلًا، والرفض يُسجَّل فعلًا، والحذف مرفوض فعلًا.

---

## شغّله

```bash
python3 ops/server.py          # http://localhost:8080
PORT=9000 python3 ops/server.py
python3 ops/test_console.py    # 35 اختبارًا — تتطلب خادمًا يعمل
```

**بلا تبعيات.** لا `npm install`، لا `pip install`، لا قاعدة بيانات خارجية.
مكتبة Python القياسية فقط. أول تشغيل يبني `ops/ops.db` ويزرعه تلقائيًا.

لإعادة التجربة من الصفر: `rm ops/ops.db*` ثم أعد التشغيل.

## ما الذي يعمل فعلًا

| | |
|---|---|
| **٤ وكلاء** | رئيس العمليات، المحاسب، خبير التسويق، متابع المهتمين |
| **مطابقة مالية** | تعدّ الحالات لا تطرح المجاميع — تجد الست تحت فرق 500 دج |
| **مستند الأستاذ** | يُعيد `basis: null` ويُظهر **الفارق بين الأسس الثلاثة** (2700/4500/5400) |
| **قمع التسويق** | 27 مهتمًا، 12 بلا رد (44.4%)، ثلاث أولويات مرتّبة + تسليم للمحاسب |
| **طابور الرد الأول** | 12 مسوَّدة من دليل الرد الأول، محسوبة ساعات انتظارها |
| **ملخص يومي** | 4 أقسام، `days_open` إلزامي، `broken` لا يُكتم، `missing` حاضر دائمًا |
| **موافقة/رفض** | الموافقة تُنفَّذ في القاعدة. الرفض **بلا سبب مرفوض** |
| **سجلّ تدقيق** | كل فعل — بما فيه الرفض و«لا أعرف» والامتناع |
| **`/revoke`** | يوقف وكيلًا فورًا فلا يقترح شيئًا في التشغيل التالي |
| **`idempotency_key`** | تشغيل الوكلاء مرتين لا يكرّر اقتراحًا |

## لماذا لا يحتاج هؤلاء الوكلاء نموذج لغة

سؤال يستحق إجابة صريحة، لأن النظام كله مبني عليها.

**المطابقة عدّ وحساب. التشخيص ترتيب ومقارنة. الملخص تجميع.** لا شيء منها يحتاج
توليد لغة. وما يحتاج لغةً — صياغة ردّ لولي أمر — عنده **8 ردود جاهزة** في
`marketing/first-reply-playbook.md`، فمطابقة قاعدة أولى **أأمن من التوليد لأنها
لا تستطيع الاختراع**.

هذا ليس تبسيطًا للأمر؛ إنه **أقوى**: الوكيل الحتمي لا يهلوس، ولا يخترع رقمًا،
ولا يحتاج `【تحقّق】` لأن كل رقم فيه مصدره استعلام.

**ما يبقى لنموذج اللغة:** صياغة منشور جديد، وردّ على حالة لم يغطّها الدليل،
وتلخيص ملاحظات أستاذ حرّة. تلك تُبنى في Claude Project بأنظمة `07-prompts/` —
وهي **الطبقة الثانية**، لا الأولى.

## كيف تُفرَض القواعد (لا كيف تُطلب)

هذا هو المبدأ الذي يميّز النظام، وهو مُختبَر لا موعود:

| القاعدة | كيف تُفرَض | الاختبار |
|---|---|---|
| الوكيل لا يكتب | اتصال بـ `PRAGMA query_only=ON` — المحرّك يرفض، لا التعليمات | `[١]` |
| لا حذف لأي سبب | `trigger` على كل جدول — **ولو على اتصال المؤسس** | `db.py` |
| السجلّ لا يُمحى | `trigger` يمنع `UPDATE` و`DELETE` على `agent_audit_log` | `[١٠]` |
| لا نشر ولا إرسال آليًا | **لا يوجد لهما تنفيذ في الكود.** `approved` و`executed_at=NULL` للأبد | `[٤]` |
| الضغط مرتين لا ينفّذ مرتين | `idempotency_key UNIQUE` | `[٧]` |
| الرفض يُعلّم الوكيل | رفض بلا سبب → `400` | `[٦]` |
| لا مستند على أساس غير محسوم | `share_basis IS NULL` → `amount_due = NULL` | `[٢.٥]` |
| الطوارئ | `/revoke` → الوكيل يُتخطّى في كل تشغيل | `[٨]` |
| لا مسار مخترع | `404` صريح | `[١٢]` |

**القاعدة الأهم، وكيف تُفرَض:** `publish_post` و`send_parent_msg` ليسا ممنوعين
بتعليمة — بل **غير موجودين في `engine.EXECUTABLE`**. الموافقة عليهما تُسجَّل،
ثم لا يجد المحرّك تنفيذًا فيعيد إليك التعليمة: «انسخ النص وانشره من حسابك».
لا يمكنك أن تطلب من برنامج تنفيذ دالة غير مكتوبة فيه.

## ما ليس هذا — بصراحة

١. **ليست قاعدة إنتاجك.** البيانات من `tests/fixtures`، مختلَقة بالكامل،
   بأسماء مستعارة. لا اسم طفل حقيقي ولا مبلغ حقيقي.

٢. **SQLite لا PostgreSQL.** الفرق جوهري:

| | هنا (SQLite) | `tech/01-schema.sql` (Postgres) |
|---|---|---|
| قراءة الوكيل فقط | `PRAGMA query_only` لكل اتصال | مستخدم `agent_*_read` بصلاحيات `REVOKE`d |
| منع الحذف | `trigger` | `trigger` + `REVOKE DELETE` |
| منع `DROP TABLE` | ⚠️ **غير ممنوع على اتصال المؤسس** | `REVOKE` شامل |
| عزل الوكلاء عن جداول بعضهم | ⚠️ غير مفروض | كل وكيل يرى `views` مخفّضة فقط |

   **الاختبار `[٩]` يثبت أن الوكيل لا يرى الجداول المالية؟ لا — يثبت أن
   `query_only` يمنعه من الكتابة.** العزل بين الوكلاء يتطلب Postgres.

٣. **الساعة مثبّتة** على `2026-11-04T07:00` في `engine.NOW` كي تكون النتائج
   قابلة للتكرار في الاختبارات. للتشغيل الحقيقي استبدلها بـ `datetime.now()`.

٤. **لا تيليجرام ولا Claude.** الـ UI هنا هو ما سيصير بوت تيليجرام لاحقًا
   (`tech/03-integrations.md`). والملخص اليومي هنا هو نفسه الذي سيرسله البوت 7:00.

٥. **لا مصادقة.** أي من يفتح المنفذ يوافق ويرفض. مقبول محليًا،
   **غير مقبول منشورًا** — قبل أي نشر عام أضف مصادقة، أو أبقِه على `localhost`.

| الخطوة | ما يتغيّر | الجهد |
|---|---|---|
| **الآن** | جرّبه محليًا، شغّل الاختبارات، اضغط موافقة ورفض بنفسك | — |
| ١ | استبدل `engine.NOW` بالساعة الحقيقية | سطر |
| ٢ | وصّل قراءاتك الحقيقية: استبدل استعلامات `agents.py` بجداولك | أنت المبرمج |
| ٣ | انقل إلى Postgres ونفّذ `tech/01-schema.sql` — هنا تُفرَض الصلاحيات الحقيقية | يوم |
| ٤ | أضف بوت تيليجرام يستهلك نفس نقاط `/api/*` — **بلا تغيير في المنطق** | يومان |
| ٥ | أضف طبقة Claude للصياغة الحرّة، تقرأ من نفس الـ API | — |

**النقطة ٤ هي سبب هذا التصميم:** البوت والواجهة يستهلكان نفس العقد،
فلا منطق مكرر ولا نسختان من الحقيقة.
